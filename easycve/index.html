How these filters work
  • All filters combine together (AND, not OR). Filling in "CVE ID contains" and "Vendor / product contains" shows only rows that match both — it narrows the results, it doesn't broaden them.
  • Text filters are partial and case-insensitive. "CVE ID contains" matches anywhere in the ID, so 2026 or 63077 both work — you don't need the full CVE-2026-63077. Same for description/name and vendor/product.
  • "Description / name contains" searches two fields at once — the vulnerability name and the short description — so a product name that only appears in one or the other will still match.
  • "CWE contains" matches against a CVE's weakness classification(s) — e.g. CWE-502 is deserialization of untrusted data, CWE-79 is cross-site scripting. A CVE can have more than one CWE; this matches if any of them contain your text. Not every CVE has one, so entries without a CWE won't match a non-empty filter here.
  • Date ranges are inclusive on both ends: a "from" date matches vulnerabilities added or due on that exact day too, not just after it.
  • Leave either side of a date range blank to leave that side open. Setting only a "from" date returns everything from that date through the most recent entry, with no upper limit. Setting only a "to" date returns everything up through that date, with no lower limit.
  • Empty filters are ignored entirely. A blank field never excludes rows — it simply isn't applied, so leaving everything blank shows the full catalog.
  • Shareable links only encode the filters you've actually set — blank fields are simply left out of the URL.
